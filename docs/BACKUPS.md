# Резервная копия облачной базы — только для владельца

Телефон и Google Диск могут принадлежать разным аккаунтам. Подключается аккаунт Google, выбранный в браузере при настройке. Клиентам планёра доступ к этому Диску не предоставляется.

## Что подготовлено

Workflow **Encrypted database backup** запускается ежедневно в **04:23 по Москве** (01:23 UTC) и вручную через Actions → Run workflow. GitHub может задержать расписание; в публичных репозиториях расписание отключается после 60 дней без активности. Отказ/приостановка Supabase тоже может помешать копированию. Проверяйте зелёные запуски и дату свежего файла на Диске.

Сохраняются схемы PostgreSQL `public`, `temoraxis_private`, `auth`: документы всех пользователей, правила и функции приложения, хеш приглашения, пользователи и данные аутентификации. Это **копия данных приложения и его пользователей**, а не образ всей инфраструктуры Supabase: файлы Storage, роли PostgreSQL, настройки SMTP/OAuth/API, Edge Functions и прочие схемы не входят. Звуковые файлы с устройств также не входят.

Копия — custom dump PostgreSQL, зашифрованный **age** публичным ключом. На GitHub закрытого ключа расшифровки нет. Успешность `pg_dump`, перечень обязательных схем и контрольная сумма загруженного зашифрованного файла проверяются перед очисткой. Проверка оглавления не заменяет периодическую пробу восстановления.

На Диске сохраняются **14 последних успешно загруженных копий**, а не строго 14 календарных дней. После проверенной загрузки лишние копии удаляются **без корзины**. Очистка ограничена выбранной папкой, меткой проекта, форматом имени и файлами, созданными данным OAuth-приложением. Другие файлы не удаляются. При сбое загрузки/проверки старые копии остаются. Неуспешная проверка может оставить дополнительный файл; его можно удалить вручную после проверки рабочего архива. Автоматическая очистка не гарантирует, что база уже не содержала ошибку/вредоносное изменение; сохраняйте также долгосрочную копию отдельно.

## 1. Ключ расшифровки

Установить age из официального источника https://github.com/FiloSottile/age/releases и выполнить локально:

```text
age-keygen -o temoraxis-backup-key.txt
```

В файле находится секретный `AGE-SECRET-KEY-…`, а строка `# public key: age1…` — публичный адрес получателя. Секретный файл сохранить отдельно от Google Диска с копиями, желательно ещё на флешке. Не отправлять в чат, GitHub или в репозиторий. Без него восстановление невозможно. Можно использовать приватный ключ, отдельно подготовленный помощником: не генерируйте новый ключ поверх используемого.

В GitHub → [Settings → Secrets and variables → Actions](https://github.com/dfkzg/Temoraxis/settings/secrets/actions) добавить **BACKUP_AGE_RECIPIENT**: только `age1…` без комментария. Публичный ключ не раскрывает данные и не позволяет расшифровать архив.

## 2. Подключение Google Диска

Создать собственный OAuth-клиент (бесплатно, без подключения платёжного аккаунта):

1. В https://console.cloud.google.com/ создать проект **Temoraxis backups** под аккаунтом с нужным Диском.
2. APIs & Services → Library → **Google Drive API** → Enable.
3. Google Auth Platform → Branding: название, контактный email. Audience → External. Добавить свой адрес Google как test user, если мастер требует тестовый режим.
4. Data Access: добавить только scope **`https://www.googleapis.com/auth/drive.file`**. Этот scope даёт доступ к созданным/выбранным через приложение файлам, а не всему Диску.
5. Clients → Create client → **Desktop app**, имя Temoraxis backup setup. Скачать JSON клиента на свой ПК. Это не service account: личному Диску не нужен сервисный аккаунт и не нужно делиться всей папкой с чужим адресом.
6. Audience → **Publish app / In production**. Иначе refresh token внешнего приложения в режиме Testing обычно перестаёт работать через 7 дней. Для личного использования с `drive.file` обычно не нужна платная проверка; если Google требует проверку, не добавляйте более широкие scopes и не отключайте защиты — сообщите, что показано. Не публикуйте client secret.
7. На ПК с Python 3.10+ запустить `tools/backup/connect_drive.py` (на Windows — `connect_drive.cmd`). Выбрать скачанный JSON. В браузере выбрать **аккаунт с нужным Google Диском** и разрешить создание файлов приложения. Программа использует OAuth со state и PKCE, пароль Google не получает.
8. Помощник создаст отдельную папку **Temoraxis — резервные копии** и предложит сохранить `google-drive-secret.json` локально. Вставить **всё содержимое файла** в GitHub Secret **BACKUP_GOOGLE_DRIVE_JSON**. Не присылать файл в чат. Старые папки при повторном подключении не удаляются.

Доступ можно отозвать в https://myaccount.google.com/connections . После отзыва копирование остановится, уже созданные копии останутся на Диске. Папку не делать общедоступной. Политики Google Workspace могут ограничивать согласие; обычный личный аккаунт подходит. 15 ГБ делятся между Drive, Gmail и Photos; при заполнении загрузка завершится ошибкой, старые копии не удалятся для освобождения места.

## 3. Доступ к PostgreSQL

Supabase → **Connect → Session pooler → URI**. Использовать порт **5432**, не transaction pooler 6543. Заменить `[YOUR-PASSWORD]` на пароль PostgreSQL; специальные символы пароля должны быть percent-encoded для URI. Это пароль базы, не пароль пользователя планёра.

Сохранить полную строку в GitHub Secret **SUPABASE_BACKUP_DB_URL**. Не вставлять в чат. Скрипт извлекает параметры в переменные окружения и принудительно использует TLS **verify-full**, системные корневые сертификаты и проверку имени сервера; параметры URI не могут отключить проверку. Пароль не передаётся аргументом процесса и не выводится в журнал. Подходит pg_dump 17 для серверов PostgreSQL 17 и более старых; при обновлении Supabase на более новую major-версию нужно обновить клиент и повторить тест восстановления.

У стандартного postgres-доступа широкие права. GitHub Secrets защищает хранение, но исполняемый workflow получает секрет; не запускайте backup из недоверенной ветки, не разрешайте незнакомым менять workflow. Копия и доступ к Google Диску не входят в APK, JSON-экспорт или опубликованные артефакты Actions. При ошибке подключения подробный stderr PostgreSQL намеренно не публикуется, чтобы не раскрыть приватные параметры.

## 4. Первый запуск

[GitHub Actions → Encrypted database backup](https://github.com/dfkzg/Temoraxis/actions/workflows/backup.yml) → Run workflow → main. До первого успешного запуска резервирование **не считается включённым**. Проверить зелёный запуск и новый `.dump.age` на Диске. В GitHub Settings → Notifications включить уведомления о неуспешных Actions; проверить, что они доходят.

Раз в несколько месяцев скачивать свежую копию и пробовать восстановление в отдельном PostgreSQL/тестовом Supabase. Не проверять восстановление поверх рабочей базы.

## Восстановление

Сохранить оригинал копии. На доверенном локальном компьютере:

```text
age --decrypt --identity temoraxis-backup-key.txt --output database.dump temoraxis-….dump.age
pg_restore --list database.dump
```

Это раскрывает также данные Auth, поэтому расшифрованный файл нельзя публиковать. Для чистого локального PostgreSQL сначала создать роли, на которые ссылаются политики, и проверить оглавление/расширения, затем `pg_restore --no-owner --no-acl --dbname=… database.dump`. Пароль подключения задавать через защищённый pgpass/окружение, а не историю команд.

В новом Supabase схема `auth` уже существует: **не запускать полное восстановление/--clean поверх неё вслепую**. Восстановить совместимые функции/схемы приложения и данные Auth по плану миграции для данной версии, сохранив рабочие роли и внешние ключи. При восстановлении в другой проект обновить URL/public key и настройки Auth, сбросить старые сессии и проверить вход/изоляцию аккаунтов. Отдельного автоматического восстановления поверх рабочего сервера в проекте нет; сначала обязательна проба на копии.
