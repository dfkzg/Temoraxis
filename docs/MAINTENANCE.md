# Обслуживание и разработка Temoraxis

Инструкции для владельца сервера и разработчиков. Команды выполняются из корня проекта.

Автоматическая сборка и публикация: [GITHUB-SETUP.md](../GITHUB-SETUP.md).

## Что находится в комплекте

- `android/` — исходники Android-приложения, проект для Android Studio, Gradle Wrapper и альтернативный скрипт сборки.
- `server/` — сервер синхронизации на Python 3.11+ и SQLite без внешних Python-зависимостей.
- `server/web/` — веб-интерфейс для ПК и PWA для телефона, включая iPhone.
- `compose.yaml`, `Caddyfile`, `.env.example` — запуск на VPS с HTTPS.
- `web-source/`, `sync.js`, `sync.css`, `stage_web.py` — исходные HTML и сборка общего интерфейса.
- `tests/` — проверки сервера, правил Android-напоминаний и сценариев синхронизации.
- `TEST-REPORT.md` — что фактически проверено и какие проверки ещё нужны.

## Размещение сервера

Понадобятся VPS с Docker Compose, домен и доступ к портам 80/443. Минимальный ориентир для нескольких пользователей — 1 CPU, 1 ГБ RAM, 10–20 ГБ диска. Точный тариф выбирается отдельно.

1. Направьте A-запись выбранного домена на IP VPS. Если добавлена AAAA-запись, IPv6 тоже должен вести на этот VPS.
2. Распакуйте проект на VPS.
3. Скопируйте `.env.example` в `.env`.
4. Укажите реальный `PLANNER_DOMAIN`, например `planner.example.ru`.
5. Создайте случайный `PLANNER_INVITE_CODE` длиной не меньше 16 символов. Пример команды генерации: `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`. Не оставляйте значение-заглушку.
6. В папке проекта выполните `docker compose up -d --build`.
7. Проверьте `https://ВАШ-ДОМЕН/api/health`: ответ должен содержать `"ok": true`.

Caddy получает бесплатный HTTPS-сертификат автоматически. Сервер приложения не публикует порт 8080 наружу; снаружи доступны только Caddy и HTTPS. Сервер не создаётся, не публикуется и не оплачивается сам по себе при распаковке архива.

### Аккаунты

Откройте **Настройки → Синхронизация устройств** в APK или на сайте. Укажите HTTPS-адрес, придумайте логин и пароль длиной от 10 символов, введите код приглашения и нажмите «Создать аккаунт».

На своём ПК войдите в тот же аккаунт. Друг регистрирует отдельный аккаунт со своим логином и паролем; его данные изолированы от ваших. Владелец сервера может изменить код приглашения после регистрации друзей.

Пароли хранятся как scrypt-хеши с индивидуальной солью; сервер хранит хеши токенов, срок сессии — 30 дней. Тела запросов и пароли не записываются в журнал. Задачи хранятся в SQLite без сквозного шифрования: администратор сервера имеет доступ к базе.

### Поведение синхронизации

- Синхронизируются задачи, отметки повторений, шаблоны часов, расписания дат, особые даты, теги и ссылки экспресс-панели.
- Тема, громкость, разрешения и аудиофайлы остаются настройками конкретного устройства.
- Проверка выполняется при открытии подключённого приложения, возврате в него и раз в минуту, пока оно открыто. Есть кнопка ручной синхронизации.
- Без интернета изменения сохраняются локально.
- При разных изменениях с двух устройств появляется выбор версии. Автоматического объединения отдельных полей нет. Перед загрузкой серверной версии сохраняется предыдущая локальная копия; её можно вернуть из окна синхронизации.
- Удаление задачи сохраняет техническую отметку `deleted`, чтобы после синхронизации задача не появилась снова. Старые удалённые записи очищаются по сроку истории.
- JSON-копии и резервные копии SQLite остаются полезными: синхронизация не заменяет независимый бэкап.

## Администрирование и резервное копирование

Показать пользователей: `docker compose exec app python admin.py list-users`.

Сменить пароль: `docker compose exec app python admin.py reset-password ЛОГИН`. Все сессии этого пользователя будут отозваны.

Создать пользователя без регистрации в интерфейсе: `docker compose exec app python admin.py create-user ЛОГИН`.

Создать согласованную резервную копию SQLite:

```
docker compose exec app python admin.py backup /app/data/backup-2026-11-14.sqlite
```

Путь должен быть новым. Копию нужно забрать на другой носитель или сервер. Не публикуйте каталог `data` и резервные копии как статические файлы. При восстановлении остановите приложение и замените основной файл базы подготовленной SQLite-копией; старые файлы `-wal`/`-shm` не смешивайте с другой копией.

Обновление: сохраните резервную копию, замените исходники, выполните `docker compose pull`, затем `docker compose up -d --build`.

## Сборка и проверки

Сначала выполните `python stage_web.py`: HTML из `web-source` объединится с кодом синхронизации и скопируется в Android и сервер.

Android Studio: откройте каталог `android`, установите SDK Platform 35 и Build Tools 35.0.0, выберите JDK 17+ и соберите `app → assembleDebug`. CLI: `android/gradlew -p android assembleDebug` (на Windows — `gradlew.bat`). Первому запуску нужен интернет для Gradle/Android Gradle Plugin.

Альтернативная сборка без Gradle:

```
python android/build.py --sdk ПУТЬ_К_ANDROID_SDK --output planner-test.apk
```

Нужны JDK с `javac`, Android SDK Platform 35 и Build Tools 35.0.0. Если доступна только JRE, скрипт поддерживает параметр `--compiler-jar` для Eclipse ECJ 3.39.0. Инструменты SDK, JDK и ECJ в архив не включены. Тестовый ключ скрипт создаёт локально в `android/debug.keystore`; храните его, если хотите подписывать обновления тем же ключом.

Проверки API: `python tests/test_server.py`. Для браузерных тестов нужен Playwright/Chromium; команды перечислены в `TEST-REPORT.md`.

Локальная разработка сервера без Docker: задайте переменные `PLANNER_INVITE_CODE`, `PLANNER_ALLOW_HTTP=1`, затем запустите `python server/server.py`; адрес — `http://127.0.0.1:8080`. HTTP на localhost предназначен для разработки. APK подключается только по HTTPS.
